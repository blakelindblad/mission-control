Building AgentPay: Our Technical Decisions

Why we chose this stack and how we solved the unique challenges of agent financial infrastructure

When we started building AgentPay, we knew we weren't just building another fintech dashboard. We were creating financial infrastructure for a new class of economic actors that operate at machine speed, make decisions algorithmically, and need zero-latency policy enforcement.

Here's how we approached the technical challenges and why we made the choices we did.

Our Tech Stack: Built for Speed and Scale

Our core stack:

  • Frontend: Next.js 14 with TypeScript
  • API Layer: tRPC for end-to-end type safety
  • Database: PostgreSQL with Prisma ORM
  • Card Issuing: Stripe Issuing API
  • Infrastructure: Vercel + Railway
  • Monitoring: Sentry + Grafana

Why Next.js + tRPC?

We needed to move fast without breaking things. tRPC gives us full-stack type safety, which means we catch API contract violations at compile time rather than in production. When you're dealing with financial transactions, runtime errors aren't just bugs—they're potential compliance disasters.

PostgreSQL: The Right Tool for Financial Data

We considered MongoDB and other NoSQL options, but financial data demands ACID transactions. When an agent attempts a purchase, we need to atomically check balances, update limits, and log the transaction. PostgreSQL's mature transaction handling and JSON support gave us the best of both worlds.

The Unique Challenges of Agent Financial Infrastructure

Challenge 1: Millisecond-Level Policy Decisions

Human transactions happen over seconds or minutes. Agent transactions happen in milliseconds. We needed to validate spending policies, check balances, and approve/decline transactions in under 100ms to avoid timeout errors.

Our solution: aggressive caching with Redis and precomputed policy rules. Instead of calculating policy compliance on each transaction, we precompute approval matrices and cache them by agent+merchant combinations.

Challenge 2: Contextual Transaction Logging

Traditional card transactions have minimal context—merchant, amount, timestamp. Agent transactions need rich metadata about the task, reasoning, and business justification for auditing and reconciliation.

We extended Stripe's webhook system to capture custom metadata that agents include with each transaction request. This data gets stored in our PostgreSQL instance with full-text search capabilities for easy auditing.

Challenge 3: Dynamic Limit Management

Agent spending patterns are unpredictable. A machine learning agent might need $50/day normally, then $5,000 for a training run. We needed flexible limit systems that could adapt programmatically.

Real-Time Policy Enforcement Architecture

This was the hardest part. We built a policy engine that can evaluate complex spending rules in real-time:

// Policy engine evaluates rules like: // "Agent can spend up to $500/day on AWS, // but only during business hours, // and only if project budget has remaining funds" class PolicyEngine { async evaluateTransaction(transaction: AgentTransaction) { const policies = await this.getPoliciesForAgent(transaction.agentId); for (const policy of policies) { const result = await policy.evaluate(transaction); if (result.deny) { return { approved: false, reason: result.reason }; } } return { approved: true }; } }

We use a rule-based system with time-based caching to ensure sub-100ms response times even for complex multi-condition policies.

Security and Compliance: Built-In, Not Bolted-On

Financial infrastructure requires security by design. Here's how we approached it:

  • Zero-Trust Architecture: Every API call is authenticated and authorized, even internal services
  • Encryption Everywhere: All sensitive data encrypted at rest and in transit using AES-256
  • Immutable Audit Logs: Every transaction and policy decision is logged immutably for compliance
  • PCI Compliance: We never touch card data directly—all payments flow through Stripe's PCI-compliant infrastructure
  • Rate Limiting: Aggressive rate limiting to prevent both accidental and malicious abuse

Monitoring: Because Finance Can't Go Down

We monitor everything: API response times, database query performance, Stripe webhook delivery rates, and policy engine decision latencies. Financial infrastructure has zero tolerance for downtime, so we built comprehensive alerting from day one.

What We Learned

Building financial infrastructure for AI agents taught us that the future of fintech isn't just digital—it's algorithmic. Agents don't just need different UIs; they need fundamentally different financial primitives.

The hardest part wasn't the technical complexity—it was reimagining financial controls for actors that don't think like humans. Traditional expense management assumes human judgment and post-hoc reconciliation. Agent finance requires programmatic guardrails and real-time decision making.

But when it works, it's magical. Agents can operate autonomously within clear financial boundaries, making your business more efficient while reducing financial risk. That's the future we're building toward, one transaction at a time.
