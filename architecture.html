AgentPay Technical Architecture

Stack Overview

Frontend: Next.js 15, TypeScript, Tailwind CSS

Backend: tRPC v11, Next.js API routes

Database: Postgres (Neon), Prisma ORM

Payments: Stripe Issuing API

Deployment: Vercel (edge functions)

Auth: Clerk

Frontend (Next.js)

  • App Router with Server Components for performance
  • Tailwind + Shadcn/ui component library
  • React Query for client state management
  • TypeScript strict mode, no any types
  • Responsive-first design (mobile → desktop)

// Type-safe API calls
const { data: cards } = api.cards.list.useQuery({ limit: 10 });

Backend (tRPC)

  • End-to-end type safety from DB → frontend
  • Zod schemas for input validation
  • Middleware for auth, rate limiting, logging
  • File structure: server/api/routers/*.ts

export const cardsRouter = createTRPCRouter({
  list: protectedProcedure
    .input(z.object({ limit: z.number().min(1).max(100) }))
    .query(async ({ ctx, input }) => { ... })
});

Database (Postgres)

  • Prisma schema with strict relations
  • Row-level security (RLS) for multi-tenant isolation
  • Indexes on: user_id, card_id, created_at
  • Separate schemas: public (app), stripe (webhook data)

model VirtualCard {
  id         String   @id @default(uuid())
  stripeId   String   @unique
  userId     String
  balance    Int      // cents
  createdAt  DateTime @default(now())
  
  user       User     @relation(fields: [userId], references: [id])
  @@index([userId])
}

Payments (Stripe Issuing)

  • Stripe Issuing for virtual card creation
  • Webhooks for real-time transaction sync
  • Store minimal Stripe data locally (IDs, status)
  • Idempotency keys for all mutations

// Card creation flow
const stripeCard = await stripe.issuing.cards.create({
  cardholder: cardholderID,
  currency: 'usd',
  type: 'virtual',
  spending_controls: { spending_limits: [{ amount: budget }] }
});

Deployment (Vercel)

  • Edge functions for API routes (tRPC)
  • Static generation for marketing pages
  • Environment-specific configs: dev, staging, prod
  • Database migrations in CI/CD (Prisma)

Key Architectural Decisions

Why tRPC over REST?

Type safety eliminates entire classes of bugs. API contract stays in sync automatically.

Why Postgres over NoSQL?

Financial data needs ACID transactions. Relational queries for spend analytics.

Why Stripe Issuing vs building cards?

Compliance nightmare. Stripe handles PCI, KYC, AML. We focus on product.

Why Vercel over AWS?

Developer velocity > infrastructure control. Zero-config deployments, edge globally.

Non-Functional Requirements

  • Latency: <200ms API responses, <1s page loads
  • Security: SOC 2 Type II, encryption at rest/transit
  • Availability: 99.9% uptime (Vercel SLA)
  • Scalability: Handle 10K users with current architecture

Phase 1 Implementation

  • Auth + user management (Clerk)
  • Virtual card dashboard (read-only Stripe data)
  • Transaction history and filtering
  • Basic spend controls and limits
